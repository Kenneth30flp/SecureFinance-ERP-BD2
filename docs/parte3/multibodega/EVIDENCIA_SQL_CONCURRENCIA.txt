DEFECTOS REALES DESCUBIERTOS Y CORREGIDOS DURING ESTE QA
--------------------------------------------------------
1. CONVERT(VARCHAR(16), Version, 2) sobre una columna rowversion entrega los 8 bytes
   RAW (no hex no imprimible) en SQL Server 2025: el campo Version del recibo JSON
   (82/83) salia corrupto y el servicio (regex ^[0-9a-f]{16}$ en validation.js) no
   podia usarlo para el bloqueo optimista. Fix aplicado en 82_P3_BOD_Transferencias.sql
   (L26/L75) y 83_P3_BOD_Administracion.sql (L34):
   CONVERT(VARCHAR(16), CAST(Version AS varbinary(8)), 2)  -> hex sin 0x, 16 chars.
   Confirmado en vivo: recibo { "...Version":"0000000000000A35", ... }.
   Reinstalacion unica de procs 82/83 en el lab via database/tests/
   P3_BOD_ReaplicarTransferencias.sql (transaccion externa, sin tocar tablas).
